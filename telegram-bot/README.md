# Telegram-бот «Планы» (aiogram 3)

Чистый Telegram-бот на Python + aiogram 3 с персональными SQLite базами данных пользователей в `PlanesUser/`.

## ✨ Что добавлено и исправлено

### 1. Персональный часовой пояс пользователя + `/changeTime` и кнопка «⚙️ Настройка времени»
- **В самом начале работы с ботом** бот предлагает выбрать **город или IANA-зону** (Москва, Алматы, Киев, Europe/Moscow, Asia/Kolkata…). Для старых клиентов есть резервный режим **«🕐 По текущему времени»** — достаточно написать текущий час.
- Для IANA-зон корректно учитывается **переход на летнее/зимнее время** и смещения вида `UTC+5:30`; выбранная зона хранится в `user_settings.timezone_name`, а старое `utc_offset` остаётся как fallback.
- **Сразу после настройки** бот сообщает пояс и текущее время, а также рассказывает о команде **`/changeTime`** — её можно использовать при переезде или ошибке.
- Кнопка **«⚙️ Настройка времени»** (в нижнем меню и в инлайн-меню `/MyPlans`) открывает единый экран настройки:
  - текущего **часового пояса** (выбор города/зоны);
  - времени и включения/выключения **утренней сводки**;
  - времени и включения/выключения **вечерней сводки**;
  - пустых сводок и **тихих часов**.
- Все даты («сегодня», «завтра», окно недели `/MyPlans`, демо-задачи и фоновые уведомления `services/notifier.py`) считаются **строго по личному часовому поясу каждого пользователя**.

### 2. Кнопка «📋 Дни с задачами» (`/alldays`)
- Добавлена кнопка **«📋 Дни с задачами»** (в постоянном нижнем меню и кнопка **«📋 В какие дни есть задачи»** внутри `/MyPlans`).
- Выводит подробный список **всех дней, в которые вообще есть какие-либо задачи** (с количеством задач, временем, названиями, а также списком повторяющихся задач), и позволяет в 1 клик перейти в любой из этих дней.

### 3. Кнопка «🗑 Удалить задачу»
- Удалять задачи теперь можно из любого удобного места:
  - **В карточке конкретной задачи** — кнопка `🗑 Удалить задачу` (для разовой задачи удаляет сразу, для повторяющейся — даёт выбор: удалить **только на выбранный день** или **все повторения навсегда**).
  - **Внутри дня** — кнопка `🗑 Удалить задачу` (позволяет удалять задачи дня в 1 клик или очистить весь день целиком `💥 Удалить все задачи`).
  - **В главном меню** — кнопка `🗑 Удалить задачу` (показывает все дни с задачами и активные повторы для быстрого удаления).

### 4. Система автопулла с GitHub (как в `VigarikSQD`)
- Добавлен **`.gitignore`**, защищающий `.env` и базы данных пользователей `PlanesUser/*.db` от перезаписи при `git pull`.
- Добавлен скрипт **`update.sh`** (загрузка свежего кода через `git pull`, автообновление `requirements.txt` и перезапуск бота в `screen -dmS plans_bot`).
- Добавлен фоновый модуль **`services/auto_pull.py`**, который автоматически раз в минуту проверяет новые коммиты в GitHub (`git fetch`) и при появлении изменений сам делает `git pull`, обновляет зависимости и перезапускает бота без участия вручную. Также поддерживается команда владельца **`/update`**.

### 5. Исправленные баги
- **Падение на спецсимволах в названиях/описаниях задач**: убран конфликт `parse_mode="Markdown"` с неэкранированным текстом (`_`, `*`, `[`) — весь вывод переведён на безопасный HTML с `html.escape`.
- **Потеря команд внутри FSM**: раньше нажатие другой команды во время создания задачи записывало текст команды (например `/MyPlans`) прямо в название задачи; теперь переключение по командам и кнопкам меню работает из любого шага, добавлены кнопка `❌ Отмена` и `/cancel`.
- **Молчаливый сброс времени**: раньше опечатка во времени начала/окончания молча превращала задачу в «без времени»; теперь бот просит ввести корректное время или явно пропустить шаг.
- **Баг `seed.py` с 2037 годом и 29 февраля**: исправлена генерация стартового расписания (раньше после 22 октября тестовые планы уезжали в 2037 год, а 29 февраля вызывали `ValueError`).
- **Надёжный `setup.sh` + `.env.example`**: добавлен файл `.env.example` и резервная генерация `.env` прямо внутри `setup.sh`.

### 6. Снижение нагрузки на сервер (важно для слабого VPS)
- **Схема БД и миграции** (`CREATE TABLE`, `ALTER TABLE`) теперь выполняются **один раз за запуск процесса** для каждой базы, а не на каждое сообщение, каждую кнопку и каждый тик планировщика. Раньше это давало постоянные записи на диск.
- **`PlanesUser/_index.json`** кэшируется в памяти и перезаписывается атомарно (через временный файл), а не читается с диска на каждое событие.
- **Планировщик уведомлений** проверяет пользователей раз в **60 секунд** (было 30) и больше не делает `INSERT`/`COMMIT` при каждом тике. Добавлены индексы `plans(plan_date)` и `plans(reminder_sent, reminder_minutes)`.
- **Автопулл GitHub** проверяет обновления раз в **15 минут** (минимум 300 секунд) и делает `git pull`/`git reset` **только если коммит реально изменился**. Все git-команды ограничены таймаутом, поэтому не могут зависнуть. Раньше при отсутствии upstream `git reset --hard` мог выполняться каждую минуту.
- **Клавиатура `/MyPlans`** считает количество задач на неделю за 2 SQL-запроса вместо 14.
- **SQLite** работает с `busy_timeout=5000` и `synchronous=NORMAL` (меньше fsync на commit).

### 7. Надёжность, лимиты и мелкие фиксы
- **Лимиты длины**: название до 100 символов, описание до 1500. Длинные тексты больше не ломают карточку задачи, сводку или подпись кнопки; сообщения обрезаются безопасно (без разрыва HTML) и при необходимости разбиваются на части.
- **Напоминания повторяющихся задач** теперь работают с любым интервалом (например, «за 2 дня»), а не только «сегодня/завтра».
- **`/alldays`**: ежедневные повторяющиеся задачи больше не пропадают, если есть разовые; список дней и правил постраничный, без обрезки HTML.
- **`/database`** отдаёт консистентную копию через SQLite Backup API, а не живой файл.
- **Удаление с подтверждением**: разовая задача, «удалить все за день» и повторяющееся правило из общего меню теперь сначала спрашивают подтверждение.
- **`/status` и `/restart`** (владелец), `/help`, `/delete` и `/cancel` добавлены в список команд.
- **Логи**: `logs/bot.log` с ротацией (5 МБ × 3), глобальный обработчик ошибок `dp.errors` с уведомлением владельцу.
- **Бэкапы**: `TaskMNGR.bat` делает бэкап кода перед деплоем; `backup.sh` + cron в 04:00 каждый день сохраняют `PlanesUser` в `/root/backups/telegram-bot/planesuser-*.tar.gz` (14 дней). Владелец может сделать бэкап вручную командой `/backup`.
- **Один экземпляр**: lock-файл `bot.pid` защищает от двух одновременных polling-процессов.
- **Безопасность**: `drop_pending_updates=False` (сообщения во время рестарта не теряются), `.env` на сервере — `chmod 600`.
- **Тихие часы** (по умолчанию выключены, 23:00–08:00): напоминания ночью переносятся на утро. **Пустые сводки** можно отключить.
- **Заблокировавшие бота** помечаются и больше не получают рассылок; `TelegramRetryAfter` обрабатывается.
- **Разбор фраз**: «9 вечера», «9:30 утра», «полдень», «полночь», «1 час 30 минут», «за неделю», «через месяц»; 29 февраля задаётся и через кнопки `/everyN`.
- **31-е число** в коротких месяцах выполняется в последний день месяца (с пояснением при создании).
- **Индекс баз** `_index.json` пересобирается по файлам `PlanesUser/*.db`, если потерялся; проверяется, что файл принадлежит именно этому `telegram_id`.

### 8. Заметки и phase 2
- **📝 Заметки** (`/notes`): отдельный раздел с папками (одна папка на заметку), текстом, интерактивным чек-листом и файлами.
- **Файлы не хранятся на сервере**: бот сохраняет `file_id` и пересылает файл из чата. Если сообщение удалено — честно предупреждает «файл недоступен».
- У заметки есть дата создания/редактирования, необязательная дата, перемещение между папками, поиск и экспорт в `.md`.
- **✅ Выполнено**: для разовых задач (`plans.done_at`) и для каждого повторения (`rule_completions`). Выполненные не попадают в сводки и напоминания.
- **✏️ Редактирование** задачи: название, описание, дата/с даты, время начала/окончания.
- **⚡ `/add`** — быстрое добавление одной строкой: `/add завтра 10:00-11:00 Созвон`.
- **⏰ Напомнить позже**: кнопки +10/+30/+60 минут под напоминанием.
- **⏸ Пауза повторяющегося правила** без удаления (в разделе «Все повторяющиеся»).
- **🔎 `/find`** ищет по задачам, повторам и заметкам; **📊 `/stats`** — выполнено за 7 дней и активные задачи.
- **💬 Обратная связь** (`/feedback`) и owner-рассылка `/broadcast` (с пропуском недоступных).
- **🛡 Антиспам**: throttle по user_id и валидация `callback_data`.
- **🌍 IANA-часовые пояса**: выбор города/зоны, DST и смещения `UTC+5:30`; старый режим «по часу» остался fallback.
- **📆 Календарь на месяц** (`/calendar`): сетка дней с отметками задач, переход по месяцам.
- **📤 Экспорт `.ics`** (`/export`): задачи и повторы на 30 дней для Google/Apple Calendar.
- **📋 Шаблоны задач** (`/templates`): сохранить задачу как шаблон из карточки или создать строкой `Название | описание | 10:00-11:00 | за 30 минут`; применить на сегодня/завтра/любую дату.
- **🔔 Несколько напоминаний** на одну задачу (и на каждое повторение): пресеты 15 минут / 30 минут / 1 час / 2 часа / 1 день + своё значение; каждое отправляется отдельно и не дублируется.
- **📅 Активные планы / 🕓 История планов**: нижнее меню разделено на активные планы и историю. `/alldays` показывает только активные (сегодня и будущие) дни, `/history` — прошедшие дни и выполненные задачи.
- **📖 Полная справка**: `/help` или `/guide` — меню по разделам (планы, задачи, повторы, напоминания, заметки, шаблоны, история, поиск, экспорт, настройки, советы). Кнопка «📖 Помощь» в нижнем меню.

## 🚀 Установка и запуск на Linux VPS (как в `VigarikSQD`)

```bash
git clone https://github.com/kaitogamer123/taskmanagertgbotik.git
cd taskmanagertgbotik/telegram-bot
chmod +x setup.sh update.sh
./setup.sh
nano .env   # впиши BOT_TOKEN
./update.sh # запустит бота в фоновой screen-сессии taskbot
```

### Обновление на сервере без Git (текущий вариант)

На сервере папка `/root/telegram-bot` не является git-репозиторием, поэтому код
заливается с ПК через **`TaskMNGR.bat`** (лежит рядом с папкой `telegram-bot`):

1. `TaskMNGR.bat` → пункт **[1]** — делает бэкап `/root/telegram-bot`, заливает
   файлы, обновляет зависимости и перезапускает бота с проверкой, что процесс жив.
2. Пункт **[2]** — только перезапуск, **[3]** — логи, **[4]** — статус.

Логи также пишутся в `/root/telegram-bot/logs/bot.log` (ротация 5 МБ × 3).
В боте у владельца есть `/status` и `/restart`.
